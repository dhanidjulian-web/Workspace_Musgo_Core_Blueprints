## 📦 BAGIAN 1: ROOT SYSTEM & VAULT INFRASTRUCTURE

### 1.1 Modul & Komponen Inti
- `README.md`, `SECURITY.md`, `ARCHITECTURE.md`, `CONSTITUTION.md`: Dokumen konstitusional digital, kebijakan keamanan global, peta arsitektur 17-layer, dan manifesto kedaulatan AI.
- `.env.example`, `docker-compose.yml`, `pyproject.toml`, `package.json`: Template konfigurasi runtime, orkestrasi container, dependensi Python/Node, dan manajemen versi paket.
- `.gitignore`: Filter eksklusi aset sensitif, cache runtime, log debug, dan artefak build lokal.
- `vault/encrypted_credentials/`: Penyimpanan terenkripsi untuk kunci layanan, token API pihak ketiga, dan sertifikat internal.
- `vault/hardware_key_manager/`: Integrasi HSM (Hardware Security Module), rotasi kunci fisik, backup kunci master, dan kebijakan manajemen siklus hidup kriptografi.
- `vault/secrets_runtime/`: Injektor rahasia runtime, rotasi rahasia sesi, cache memori volatil, dan direktori lingkungan (production/staging/development/testing).
- `vault/certificate_authority/`: Root CA, Intermediate CA, generator sertifikat, pencabutan sertifikat, kebijakan penerbitan, dan repositori sertifikat server/klien.

### 1.2 Kedalaman Logika & Zero-Trust Implementation
- **Isolasi Kredensial:** Semua rahasia dienkripsi menggunakan AES-256-GCM dengan kunci utama yang hanya hidup di memori runtime atau HSM fisik. Tidak ada plaintext yang tersimpan di disk persistent.
- **Rotasi Otomatis:** Setiap token, kunci, dan sertifikat memiliki TTL (Time-To-Live) yang dikonfigurasi. Sistem secara periodik memverifikasi masa berlaku dan memicu rotasi tanpa downtime melalui mekanisme `graceful_reload`.
- **Verifikasi Integritas:** Setiap file konfigurasi dan rahasia divalidasi checksum SHA-3 sebelum dimuat. Jika hash tidak cocok, proses boot dihentikan dan memicu `emergency_lockdown`.
- **Akses Minimal:** Hanya modul yang secara eksplisit dideklarasikan dalam `capability_manifest` yang dapat mendekripsi dan membaca rahasia tertentu. Cross-module secret sharing dilarang kecuali melalui `secure_bridge` terautentikasi.

### 1.3 Task Flow (Operasional Sistem)
1. Sistem membaca `vault/encrypted_credentials/` saat inisialisasi.
2. `hardware_key_manager` memverifikasi integritas HSM dan memuat kunci dekripsi master.
3. Secrets didekripsi secara volatil ke memori, kemudian langsung diinjeksikan ke modul yang membutuhkan via `secrets_runtime`.
4. `certificate_authority` memverifikasi rantai kepercayaan sertifikat aktif. Jika ditemukan sertifikat kadaluarsa atau dicabut, koneksi terkait diputus dan dialihkan ke fallback aman.
5. Semua akses ke vault dicatat di `immutable_audit_log` dengan tanda tangan kriptografis.

### 1.4 User Flow (Interaksi Admin/Founder)
1. Founder mengunggah konfigurasi lingkungan melalui antarmuka aman atau CLI terenkripsi.
2. Sistem memvalidasi format, mengenkripsi konten, dan menyimpannya ke vault.
3. Founder dapat memantau rotasi kunci, masa berlaku sertifikat, dan log akses vault melalui dashboard terisolasi.
4. Setiap perubahan kebijakan vault memerlukan persetujuan multi-faktor dan dicatat di ledger konstitusional.

```python
"""
================================================================================
MUSGO-OS 2in1 — CREATOR ECONOMY ENGINE
VERSION: V5.0.0 (PHASE 5)
AUTHOR: AI SYSTEM ARCHITECT
STATUS: PRODUCTION_GRADE | SECURITY_FIRST

import time
import uuid
import logging
from typing import Dict, List, Optional
from datetime import datetime

logger = logging.getLogger("MUSGO_CREATOR_ECONOMY")

class AssetValidationResult:
    """Hasil validasi aset kreator."""
    def __init__(self, is_valid: bool, reasons: List[str]):
        self.is_valid = is_valid
        self.reasons = reasons

class CreatorEconomyEngine:
    """
    Mengelola seluruh aktivitas ekonomi kreator:
    1. Validasi Aset (AI Moderation + Security Scan)
    2. Reputasi & Trust Score
    3. Distribusi Produk
    """

    def __init__(self):
        self.creators_db: Dict[str, Dict] = {}
        self.asset_registry: Dict[str, Dict] = {}
        logger.info("Creator Economy Engine Initialized.")

    def register_creator(self, user_id: str) -> str:
        """Mendaftarkan pengguna sebagai kreator."""
        creator_id = f"cre_{uuid.uuid4().hex[:8]}"
        self.creators_db[creator_id] = {
            "user_id": user_id,
            "trust_score": 50, # Mulai dari netral
            "total_sales": 0,
            "joined_at": datetime.now().isoformat()
        }
        logger.info(f"New Creator Registered: {creator_id}")
        return creator_id

    def validate_asset_submission(self, asset_data: Dict) -> AssetValidationResult:
        """
        Validasi keamanan dan kualitas aset sebelum masuk marketplace.
        Mencegah malware, prompt injection, dan aset berbahaya.
        """
        reasons = []
        
        # 1. Security Scan Simulation (Anti-Malware/Exploit)
        if "malicious_code" in asset_data.get("content", ""):
            reasons.append("Security Threat Detected")

        # 2. Policy Check (Constitutional Alignment)
        if "unethical_content" in asset_data.get("tags", []):
            reasons.append("Violates Constitutional Policy")

        if reasons:
            logger.warning(f"Asset Validation Failed: {reasons}")
            return AssetValidationResult(is_valid=False, reasons=reasons)
        
        logger.info("Asset Validation Passed. Ready for Marketplace.")
        return AssetValidationResult(is_valid=True, reasons=[])

    def update_trust_score(self, creator_id: str, sales_count: int, positive_feedback: int):
        """Algoritma reputasi kreator. Semakin bagus jualan, semakin tinggi trust."""
        if creator_id in self.creators_db:
            # Logic sederhana: feedback positif menaikkan trust
            delta = (positive_feedback * 2) + (sales_count * 0.5)
            current = self.creators_db[creator_id]["trust_score"]
            new_score = min(100, current + delta)
            
            self.creators_db[creator_id]["trust_score"] = new_score
            logger.info(f"Trust Score Updated for {creator_id}: {new_score}")
```

```python
import time
import logging
from typing import Dict, List

logger = logging.getLogger("MUSGO_REVENUE_SHARING")

class RevenueSharingSystem:
    """
    Mengatur pembagian hasil transaksi secara otomatis.
    Menggunakan sistem pencatatan yang tidak bisa diubah (Immutable).
    """

    def __init__(self, platform_fee_percentage: float = 30.0):
        self.platform_fee_percentage = platform_fee_percentage # 30% untuk Platform
        self.ledger: List[Dict] = [] # Buku besar transaksi
        logger.info(f"Revenue Sharing System Initialized. Platform Fee: {platform_fee_percentage}%")

    def _generate_transaction_hash(self, transaction_data: Dict) -> str:
        """Membuat hash unik untuk keamanan data transaksi."""
        data_str = str(transaction_data)
        return hashlib.sha256(data_str.encode()).hexdigest()

    def process_revenue_split(self, transaction_id: str, amount: float, creator_id: str):
        """
        Membagi uang dari satu transaksi.
        Logic: 
        - Platform Fee (Misal 30%)
        - Creator Share (Misal 70%)
        """
        # 1. Hitung pembagian
        platform_share = amount * (self.platform_fee_percentage / 100)
        creator_share = amount - platform_share

        transaction_record = {
            "timestamp": time.time(),
            "transaction_id": transaction_id,
            "total_amount": amount,
            "platform_share": platform_share,
            "creator_share": creator_share,
            "creator_id": creator_id,
            "status": "DISTRIBUTED"
        }

        # 2. Keamanan: Hash transaksi untuk audit
        transaction_record["audit_hash"] = self._generate_transaction_hash(transaction_record)

        # 3. Catat ke Immutable Ledger
        self.ledger.append(transaction_record)
        
        logger.info(f"Revenue Distributed: TxID={transaction_id} | Creator Gets: {creator_share}")
        return transaction_record

    def get_ledger(self) -> List[Dict]:
        """Mengambil seluruh riwayat transaksi (Read Only)."""
        return self.ledger

# Contoh Penggunaan
if __name__ == "__main__":
    system = RevenueSharingSystem(platform_fee_percentage=30.0)
    # Simulasi penjualan template seharga 100.000
    system.process_revenue_split("tx_999", 100000, "cre_abc123")
```

### 📂 FILE 3: `marketplace_ecosystem/monetization_orchestrator/`
**Fungsi:** Mengatur "Tier" (Jenis langganan). Siapa yang Free, siapa yang Pro, siapa yang Enterprise. File ini mengunci fitur berdasarkan tier (Feature Gating).

```python
"""
================================================================================
MUSGO-OS 2in1 — MONETIZATION ORCHESTRATOR
VERSION: V5.0.0 (PHASE 5)
AUTHOR: AI SYSTEM ARCHITECT
STATUS: PRODUCTION_GRADE | SUBSCRIPTION_MANAGEMENT
================================================================================
"""
import logging
from typing import Dict, List, Optional
from datetime import datetime, timedelta

logger = logging.getLogger("MUSGO_MONETIZATION")

class TierConfig:
    """Definisi Batasan per Tier."""
    def __init__(self, name: str, price: float, max_ai_requests: int, features: List[str]):
        self.name = name
        self.price = price
        self.max_ai_requests = max_ai_requests
        self.features = features

class MonetizationOrchestrator:
    """
    Otak dari bisnis MusGo-OS.
    Mengatur siapa boleh akses fitur apa.
    """

    def __init__(self):
        self.tiers: Dict[str, TierConfig] = {
            "FREE": TierConfig("FREE", 0.0, 10, ["basic_chat", "web_access"]),
            "LITE": TierConfig("LITE", 29000, 100, ["basic_chat", "web_access", "image_gen", "auto_suggest"]),
            "PRO": TierConfig("PRO", 99000, 1000, ["all_basic", "image_gen", "video_gen", "priority_support", "marketplace_sell"]),
            "ENTERPRISE": TierConfig("ENTERPRISE", 500000, 999999, ["unlimited", "api_access", "custom_ai", "dedicated_support"])
        }
        self.user_subscriptions: Dict[str, Dict] = {}
        logger.info("Monetization Orchestrator Initialized.")

    def subscribe_user(self, user_id: str, tier_name: str):
        """User berlangganan tier tertentu."""
        if tier_name not in self.tiers:
            raise ValueError(f"Tier {tier_name} tidak ditemukan.")
        
        tier = self.tiers[tier_name]
        self.user_subscriptions[user_id] = {
            "tier": tier_name,
            "expires_at": (datetime.now() + timedelta(days=30)).isoformat(), # Langganan 30 hari
            "requests_used": 0
        }
        logger.info(f"User {user_id} subscribed to {tier_name}")

    def check_feature_access(self, user_id: str, feature_name: str) -> bool:
        """Cek apakah user boleh pakai fitur ini."""
        if user_id not in self.user_subscriptions:
            # Default ke FREE
            user_tier = "FREE"
        else:
            user_tier = self.user_subscriptions[user_id]["tier"]

        allowed_features = self.tiers[user_tier].features
        
        if feature_name in allowed_features:
            return True
        return False

    def consume_quota(self, user_id: str, amount: int = 1):
        """Mengurangi kuota request user."""
        if user_id in self.user_subscriptions:
            tier_name = self.user_subscriptions[user_id]["tier"]
            limit = self.tiers[tier_name].max_ai_requests
            
            current_usage = self.user_subscriptions[user_id].get("requests_used", 0)
            
            if current_usage + amount > limit:
                raise PermissionError("Quota Exceeded! Silakan upgrade tier.")
            
            self.user_subscriptions[user_id]["requests_used"] = current_usage + amount
            return True
        return False
```

### 📂 FILE 4: `marketplace_ecosystem/sovereign_payment_gateway/`
**Fungsi:** Gerbang pembayaran yang aman. Menghubungkan sistem dengan dompet digital/bank. Fokus pada **Idempotency** (mencegah double charge) dan **Signature Verification** (mencegah manipulasi data bayar).

```python
"""
================================================================================
MUSGO-OS 2in1 — SOVEREIGN PAYMENT GATEWAY
VERSION: V5.0.0 (PHASE 5)
AUTHOR: AI SYSTEM ARCHITECT
STATUS: PRODUCTION_GRADE | FINANCIAL_SECURITY
================================================================================
"""
import hashlib
import time
import logging
import uuid
from typing import Dict, Optional

logger = logging.getLogger("MUSGO_PAYMENT_GATEWAY")

class SovereignPaymentGateway:
    """
    Gerbang pembayaran terenkripsi.
    Menjamin setiap transaksi unik dan aman.
    """

    def __init__(self, merchant_secret: str):
        self.merchant_secret = merchant_secret
        self.processed_transactions = set() # Cache untuk Idempotency
        logger.info("Sovereign Payment Gateway Initialized.")

    def _generate_signature(self, payload: Dict) -> str:
        """Membuat tanda tangan digital untuk transaksi."""
        # Mengurutkan key agar hasil hash konsisten
        sorted_payload = sorted(payload.items())
        data_str = str(sorted_payload) + self.merchant_secret
        return hashlib.sha256(data_str.encode()).hexdigest()

    def initiate_payment(self, amount: float, user_id: str, item_id: str) -> Dict:
        """Membuat tagihan baru."""
        transaction_id = f"musgo_tx_{uuid.uuid4().hex[:12]}"
        
        payload = {
            "amount": amount,
            "user_id": user_id,
            "item_id": item_id,
            "timestamp": int(time.time())
        }
        
        # Sign transaksi agar tidak bisa diubah di tengah jalan
        signature = self._generate_signature(payload)
        payload["signature"] = signature
        
        logger.info(f"Payment Initiated: {transaction_id} | Amount: {amount}")
        return {"status": "PENDING", "transaction_id": transaction_id, "payment_url": "https://pay.musgo-os.id/" + transaction_id}

    def verify_payment_callback(self, callback_data: Dict) -> bool:
        """
        Menerima konfirmasi pembayaran dari Bank/E-Wallet.
        Validasi tanda tangan untuk mencegah hacking.
        """
        # 1. Cek Idempotency (Apakah transaksi ini sudah diproses sebelumnya?)
        tx_id = callback_data.get("transaction_id")
        if tx_id in self.processed_transactions:
            logger.warning(f"Duplicate Transaction Detected: {tx_id}")
            return False

        # 2. Validasi Tanda Tangan
        received_signature = callback_data.get("signature")
        temp_data = {k: v for k, v in callback_data.items() if k != "signature"}
        expected_signature = self._generate_signature(temp_data)

        if received_signature != expected_signature:
            logger.error("PAYMENT TAMPERING DETECTED! Signature mismatch.")
            return False

        # 3. Tandai sebagai sukses
        self.processed_transactions.add(tx_id)
        logger.info(f"Payment Verified & Completed: {tx_id}")
        return True

# Contoh Penggunaan
if __name__ == "__main__":
    gateway = SovereignPaymentGateway("secret_key_rahasia_banget")
    
    # User bayar
    bill = gateway.initiate_payment(50000, "user_123", "template_01")
    print(f"Bill Created: {bill}")
    
    # Simulasi callback dari bank (harus punya signature yang benar)
    # Di dunia nyata, ini dikirim dari server bank
    fake_callback = {
        "transaction_id": bill["transaction_id"],
        "status": "SUCCESS",
        "amount": 50000
    }
    # Tambahkan signature yang benar
    fake_callback["signature"] = gateway._generate_signature({k:v for k,v in fake_callback.items() if k != "signature"})
    
    print(f"Verification Result: {gateway.verify_payment_callback(fake_callback)}")
```

```typescript
// src/core/tokenEngine.ts

interface ModelPricing {
  inputTokenPrice: number;  // Harga per 1k input tokens
  outputTokenPrice: number; // Harga per 1k output tokens
  baseCost: number;         // Biaya dasar per request (overhead)
}

const MODEL_PRICING: Record<string, ModelPricing> = {
  'gpt-4o-mini': { inputTokenPrice: 0.15, outputTokenPrice: 0.60, baseCost: 10 },
  'gpt-4o':      { inputTokenPrice: 2.50, outputTokenPrice: 10.0, baseCost: 50 },
  'claude-3-5':  { inputTokenPrice: 3.00, outputTokenPrice: 15.0, baseCost: 60 },
  'deepseek-v2': { inputTokenPrice: 0.10, outputTokenPrice: 0.50, baseCost: 5 },
};

const TIER_DISCOUNT: Record<string, number> = {
  'free': 1.0,       // 0% diskon
  'light': 0.95,     // 5% diskon
  'pro': 0.90,       // 10% diskon
  'enterprise': 0.80 // 20% diskon
};

/**
 * Menghitung biaya request secara dinamis.
 */
export function calculateRequestCost(
  model: string, 
  inputTokens: number, 
  outputTokens: number, 
  userTier: string
): number {
  
  const modelCost = MODEL_PRICING[model] || MODEL_PRICING['gpt-4o-mini']; // Default fallback
  
  // Rumus: (Base Cost) + (Input * Price) + (Output * Price)
  let rawCost = modelCost.baseCost + 
                (inputTokens / 1000 * modelCost.inputTokenPrice) + 
                (outputTokens / 1000 * modelCost.outputTokenPrice);

  // Terapkan diskon tier
  const discount = TIER_DISCOUNT[userTier] || 1.0;
  const finalCost = rawCost * discount;

  // Round up agar tidak ada desimal token yang membingungkan
  return Math.ceil(finalCost);
}
```

#### 🔹 Upgrade 2: `src/middleware/billingMiddleware.ts` (Async & Safe)
Menggunakan Redis untuk pengecekan saldo cepat dan Queue untuk pemotongan saldo aman.

```typescript
// src/middleware/billingMiddleware.ts
import { Request, Response, NextFunction } from 'express';
import Redis from 'ioredis';
import { Queue } from 'bullmq';

const redis = new Redis(); // Koneksi Redis
const billingQueue = new Queue('billing-deductions'); // Queue untuk pemotongan saldo async

/**
 * Middleware untuk mengecek saldo dan memasukkan job billing ke queue.
 * TIDAK memblokir response AI utama.
 */
export const billingMiddleware = async (req: Request, res: Response, next: NextFunction) => {
  try {
    const userId = req.user?.id;
    if (!userId) return res.status(401).json({ error: "Unauthorized" });

    // 1. Cek Saldo Cepat via Redis (Cache)
    const balance = await redis.get(`user:${userId}:balance`);
    
    // Jika saldo sangat rendah, warning atau block (tergantung tier)
    if (balance && parseInt(balance) < 50) {
      // Logic untuk Free User: Block jika < 50 token
      // Logic untuk Paid User: Izinkan tapi kirim email notifikasi
      if (req.user.tier === 'free') {
        return res.status(402).json({ 
            error: "Insufficient Tokens", 
            action: "Top-up required" 
        });
      }
    }

    // 2. Masukkan ke Queue Pemotongan Saldo (Async)
    // Job ini akan dieksekusi setelah AI selesai merespons
    await billingQueue.add('deduct-tokens', {
      userId,
      estimatedCost: 100, // Estimasi awal
      tier: req.user.tier
    });

    // Lanjut ke controller AI (Non-blocking)
    next();

  } catch (error) {
    console.error("Billing Middleware Error:", error);
    next(); // Fallback: izinkan request tapi catat error (fail-open strategy)
  }
};

/**
 * Worker untuk mengeksekusi pemotongan saldo setelah AI selesai.
 * (Diletakkan di file worker terpisah)
 */
export const processBilling = async (job) => {
  const { userId, finalCost } = job.data;
  
  // Gunakan Pipeline Redis untuk Atomic Operation
  const pipe = redis.pipeline();
  
  // Kurangi saldo
  pipe.decrby(`user:${userId}:balance`, finalCost);
  
  // Catat ke Ledger (Database PostgreSQL akan disinkronkan oleh worker lain)
  pipe.lpush(`user:${userId}:ledger_log`, JSON.stringify({
    type: 'deduction',
    amount: finalCost,
    timestamp: Date.now()
  }));

  await pipe.exec();
};
```

### 1. CONSTITUTIONAL VAULT & SECRETS RUNTIME (`vault/`)
**Deskripsi Arsitektural:**
Vault bukan sekadar folder penyimpanan, melainkan *Hardware-Backed Cryptographic Boundary*. Seluruh kunci privat, token API pihak ketiga (OpenAI, Anthropic, HuggingFace), dan kredensial database tidak boleh pernah menyentuh disk dalam bentuk *plaintext*. Vault bertindak sebagai satu-satunya gerbang injeksi rahasia ke dalam memori runtime (*volatile memory*) saat sistem melakukan *booting*.

**Modul & Komponen Inti:**
*   `hardware_key_manager/`: Mengelola integrasi dengan HSM (Hardware Security Module) atau TPM (Trusted Platform Module). Menyimpan `master_private.pem` yang digunakan untuk menandatangani setiap rilis kode dan memverifikasi integritas file konstitusi.
*   `encrypted_credentials/`: Menyimpan token API yang telah dienkripsi dengan AES-256-GCM.
*   `secrets_runtime/`: Mesin injeksi yang mendekripsi rahasia hanya di RAM, dengan mekanisme *auto-wipe* (penghapusan otomatis) saat proses dihentikan atau terjadi *panic dump*.

**Kedalaman Logika & Zero-Trust Implementation:**
*   **Boot-Time Integrity Check:** Saat sistem dinyalakan, `hardware_key_manager` akan membaca *binary hash* dari folder `core/`. Jika ada satu byte pun yang berubah tanpa tanda tangan digital dari `master_private.pem`, sistem akan memicu *Constitutional Lockdown* dan menolak untuk memuat rahasia apa pun.
*   **Memory-Only Decryption:** Kredensial tidak pernah ditulis ke file `.env` di server produksi. `secrets_runtime` akan mendekripsi token langsung ke variabel lingkungan proses yang terisolasi (*isolated process environment*).
*   **Ephemeral Lease:** Setiap agen AI yang membutuhkan akses ke API eksternal tidak diberikan token secara langsung. Mereka diberikan *ephemeral lease* (token sementara) yang kedaluwarsa dalam 5 menit, yang ditukarkan melalui perantara `api_gateway`.

**Task Flow (Operasional Sistem):**
1. Sistem melakukan *boot* → `sovereign_boot_orchestrator` memanggil `hardware_key_manager`.
2. HSM memverifikasi sidik jari perangkat keras → Jika cocok, kunci master didekripsi ke RAM.
3. `secrets_runtime` membaca `encrypted_credentials/` → Mendekripsi token API → Menyuntikkannya ke *secure memory pool*.
4. `Layer_09_API_Gateway` meminta *lease token* untuk memanggil model AI eksternal → Vault menerbitkan token berumur pendek yang dicatat di *immutable audit log*.

### 3. SOVEREIGN ECONOMY: UPGRADED BILLING & MONETIZATION ENGINE (`services/monetization/` & `framework/billing/`)
**Deskripsi Arsitektural:**
Berdasarkan audit terhadap dokumen *SaaS Monetization* dan *Billing Engine*, arsitektur ekonomi MusGo-OS telah di-upgrade dari model statis menjadi **Hybrid Intelligent Billing System**. Sistem ini tidak lagi memotong saldo secara sinkron (yang memperlambat respons AI), melainkan menggunakan *Asynchronous Queue*, *Dynamic Pricing*, dan *Atomic Ledger* untuk mencegah eksploitasi dan memastikan profitabilitas.

**Modul & Komponen Inti:**
*   `Dynamic Pricing Engine`: Menghitung biaya token secara *real-time* berdasarkan: (1) Biaya modal API dari penyedia (OpenAI/Anthropic), (2) Margin keuntungan sistem, (3) Diskon berdasarkan Tier User (Free, Lite, Pro, Enterprise).
*   `Async Billing Queue (BullMQ/Redis)`: Memisahkan jalur respons AI dengan jalur pemotongan saldo. User menerima jawaban AI dalam milidetik, sementara pemotongan token diproses di latar belakang (*background worker*).
*   `Token Ledger & Idempotency Guard`: Buku besar transaksi yang menggunakan *Idempotency Keys* untuk mencegah *double-charge* akibat *network retry* atau *race condition*.
*   `Anomaly & Fraud Detection`: Memantau pola *token drain* (pengurasan token tidak wajar) atau *prompt flooding* (spam permintaan) dan secara otomatis memicu *soft-throttle* (pembatasan lembut).

**Kedalaman Logika & Zero-Trust Implementation:**
*   **Atomic Reservation (Reserve-Commit-Rollback):** Saat user mengirim prompt, sistem tidak langsung memotong saldo. Sistem melakukan *Reserve* (mengunci estimasi token di Redis). Jika AI berhasil merespons, sistem melakukan *Commit* (memotong saldo sesuai token asli yang terpakai). Jika AI gagal atau *timeout*, sistem melakukan *Rollback* (melepaskan kunci tanpa memotong saldo).
*   **Model-Aware Cost Routing:** Jika user Tier Free mencoba menggunakan model mahal (misal: Claude-3.5-Sonnet) yang melebihi batas margin gratis, `API_Gateway` secara otomatis merutekan permintaan ke model yang lebih efisien (misal: DeepSeek atau GPT-4o-Mini) tanpa memberitahu user, menjaga margin tetap positif.
*   **Viral Watermark Injection:** Untuk user Tier Free, `Output_Sanitizer` akan secara otomatis menyisipkan *watermark* teks tersembunyi atau tautan referral di bagian akhir respons AI, mengubah setiap pengguna gratis menjadi agen pemasaran organik.

**Task Flow (Operasional Sistem - Async Billing):**
1. User Tier Pro mengirim prompt panjang ke model GPT-4o.
2. `Billing Middleware` mengecek saldo Redis → Saldo cukup.
3. Middleware menerbitkan *Idempotency Key* dan melakukan *Reserve* 5.000 token di Redis.
4. Request diteruskan ke `AI Runtime Core` → AI memproses dan mengembalikan respons ke User (Latensi rendah).
5. Di latar belakang, `Billing Worker` menghitung token asli yang terpakai (misal: 4.200 token).
6. Worker menghitung biaya dinamis: `(4.2 * Harga GPT-4o) * Diskon Tier Pro`.
7. Worker melakukan *Commit* ke `Token Ledger` (PostgreSQL) dan memperbarui saldo Redis.
8. Jika user menutup koneksi di tengah jalan (AI gagal), *TTL (Time-To-Live)* pada kunci *Reserve* akan kedaluwarsa, dan token dikembalikan secara otomatis.

**User Flow (Interaksi Pengguna & Kreator):**
1. **User:** Membeli paket token (Pay-As-You-Go) melalui `Sovereign Payment Gateway`. Saldo langsung terisi di Redis (Cache) dan dicatat di Database (Source of Truth).
2. **Kreator:** Mengunggah *Workflow Template* ke `Marketplace`. `Creator Economy Engine` memvalidasi aset, menetapkan harga, dan mendaftarkannya.
3. **Transaksi:** Saat User lain membeli template tersebut, `Revenue Sharing System` secara otomatis membagi pembayaran (misal: 70% ke dompet Kreator, 30% ke kas MusGo-OS) menggunakan *Smart Contract Logic* yang tercatat di *Immutable Ledger*.
