📌 KILO APP — MEMORY & SESSION BEHAVIOR
1. TOKEN 100% → APA YANG TERJADI?
Ketika token mencapai 100% dari context window:

Scenario	What Happens
Near limit (~90-95%)	Kilo mulai truncate/hapus pesan lama secara otomatis untuk memberi ruang ke pesan baru
At limit (100%)	Kilo tidak bisa menerima input baru karena context penuh
User continues typing	Kilo akan error/mengeluh bahwa context penuh
Kilo TIDAK me-reset session secara otomatis. Kilo hanya:

Mengaburkan (forget) bagian paling lama dari conversation
Menjaga pesan terbaru tetap ada
Tidak menghapus seluruh session untuk melanjutkan percakapan
2. SESI BARU — APAKAH ADA KONEKSI KE MEMORY LAMA?
SESI BARU = SEPENUHNYA BARU.

Aspect	Behavior
Chat history	TIDAK dibawa ke session baru
Memory/context	KOSONG — mulai dari awal
Files/variables	TIDAK dibawa
Recall tool	MASIH BISA — Kilo bisa recall percakapan lama via kilo_local_recall
Jadi:

Session baru = fresh start
Tapi Kilo masih bisa ingat percakapan Anda lewat tool recall
Recall ini bukan real-time memory, tapi search dari history yang tersimpan

Sesi Baru
    ↓

Kilo menggunakan `kilo_local_recall` tool
    ↓
Mencari di database lokal session history
    ↓
Menampilkan hasil pencarian
Namun ada LIMITASI:

Recall hanya bisa mencari di project/worktree yang sama
Recall tidak bisa membaca file di session yang sudah dihapus/archive
