Arsitektur inti

Control plane yang rapi, bukan terminal tempelan.

Karena app kamu mengelola banyak domain sekaligus—sandbox Linux, local storage, model provider, routing, fallback, dan swarm—arsitekturnya harus dipisah jelas: UI layer, Provider spec layer, Sandbox runtime layer, dan Agent orchestration layer.

Module map

Android app sebagai orchestrator
01 / UI

Dashboard untuk install distro, pilih terminal default, lihat storage mount, atur provider BYOK, auto-route mode, fallback chain, model pool, dan swarm topology.

02 / Sandbox

Manager untuk download rootfs / proot image, install, uninstall, update metadata, mount workspace, dan expose terminal session via Termux.

03 / Provider

Satu spec generik untuk base URL, API key, headers opsional, model discovery, routing tags, limits, dan healthcheck. Semua provider dipaksa masuk ke format External Provider spec yang sama.

04 / Router

Layer pemilihan model berdasarkan mode free, small, balance, frontier, ditambah fallback dan weighted model pools.

05 / Agent

Agent registry, tool permissions, sandbox affinity, shared memory/session context, dan swarm execution untuk planner, coder, reviewer, runner, atau file-ops agent.

Sandbox spec

Install, uninstall, mount, dan kelola file secara deterministik.

App bertugas bukan cuma “membuka shell”, tapi juga mengelola lifecycle sandbox: metadata distro, lokasi rootfs, ukuran, akses storage, mount workspace, cache, export, backup, dan permission policy.

Step 01

Catalog sandbox

Sediakan daftar Ubuntu, Debian, Kali rootless/NetHunter-like rootfs, versi, arsitektur, ukuran, checksum, dan metode install.

Step 02

Install manager

Download rootfs atau trigger proot-distro install via Termux, verifikasi integritas, lalu catat state install.

Step 03

File manager

Map local storage ke workspace sandbox: read-only docs, writable project dir, temp dir, exports, shared agent memory.

Step 04

Remove safely

Uninstall harus tahu mana rootfs inti, mana user data, mana cache, dan mana hasil export agar tidak menghapus file penting user.

External Provider spec

BYOK tunggal untuk semua model: base URL, key, pool, route, fallback.

Karena kamu minta hanya memakai Models External Provider spec, maka semua provider—apapun vendornya— harus dinormalisasi ke satu kontrak yang sama. Dengan begitu app bisa menukar model tanpa mengubah logic sandbox atau agent.

Field wajib provider

minimum viable external spec
baseUrl

Endpoint utama provider. Wajib editable oleh user untuk skenario proxy, gateway, self-hosted, atau vendor kompatibel.

apiKeyRef

Referensi ke Android Keystore / encrypted storage. Hindari menyimpan raw API key di plain JSON.

compatibility

Tipe adapter, misalnya openai-compatible atau custom schema, supaya parser request/response bisa dipilih otomatis.

models[]

Daftar model dengan tag seperti free, small, balance, frontier, tools, vision, coding, reasoning, long-context.

healthcheck

Path untuk validasi koneksi dan deteksi provider down sebelum request produksi dijalankan.

BYOK UX spec

form yang perlu disediakan
Tambah

Label provider, base URL, API key, custom headers opsional, compatibility type, test connection.

Pool

Masukkan model ke free pool, small pool, balanced pool, frontier pool, premium pool, atau pool khusus agent tertentu.

Fallback

User bisa menentukan urutan model cadangan per task atau per agent bila model utama timeout, quota habis, atau gagal tool call.

Priority

Tambahkan bobot biaya, latensi, dan kualitas agar router tidak cuma berdasarkan nama mode.

Routing & swarm

Auto-route, fallback models/agents, model pool, dan agent-swarm.

Supaya app builder kamu terasa matang, routing tidak boleh hardcoded. Ia harus berbasis policy: mode global, role agent, ukuran task, availability provider, biaya, dan tool requirements.

Mode / fitur
Aturan pemilihan
Contoh penggunaan
Auto-route / free

Prioritaskan nol biaya atau biaya sangat rendah.

Filter tags: free, zero-cost, cheap. Tolak model premium kecuali semua gagal.
Draft, title generation, ringan, summarization batch.
Auto-route / small

Utamakan latensi rendah dan response cepat.

Filter tags: small, fast, low-latency, context secukupnya.
Inline assist, command suggestions, shell hints.
Auto-route / balance

Trade-off biaya, kualitas, dan tool support.

Skor gabungan: cost score + latency score + capability score.
Coding assist, planning sedang, file operations, patch generation.
Auto-route / frontier

Pakai model terbaik yang tersedia.

Prioritaskan reasoning/tool-heavy/high-context, fallback ke balance.
Planner utama, reviewer, multi-step repair, evaluasi swarm.
Fallback models/agents

Cadangan ketika gagal.

Jika timeout atau 429/5xx, pindah ke model berikutnya atau agent eksekutor alternatif.
planner-frontier gagal → planner-balance → planner-small.
Models pool

Kumpulan model per tujuan.

Group per role, cost tier, vendor, capability.
coding-pool, free-pool, long-context-pool, vision-pool.
Agent swarm

Beberapa agent jalan bersama.

Role map + queue + shared artifact + router per role.
planner → coder → reviewer → runner → summarizer.
Implementasi praktis

Urutan build yang paling aman untuk Android app kamu.

Berikut baseline implementasi yang konsisten dengan kebutuhanmu: Termux default terminal emulator, sandbox manager, file manager spec, BYOK provider, routing engine, lalu agent swarm orchestration.

Phase 01

Termux bridge

Buat deteksi instalasi Termux, tombol open terminal, bootstrap command templates, dan mekanisme handoff command ke session.

Phase 02

Sandbox registry

Tambah katalog Ubuntu/Debian/Kali, status install, ukuran storage, mount rules, serta flow uninstall yang aman.

Phase 03

External provider spec

Implement form BYOK: base URL, API key, adapter type, model discovery, pool assignment, healthcheck.

Phase 04

Routing & swarm

Bangun policy engine untuk free/small/balance/frontier, fallback chain, models-pool, dan role-based swarm execution.

Checklist fitur app

harus ada di builder
Sandbox add/remove

Tombol install, uninstall, reset cache, open terminal, open workspace, dan export logs.

File manager spec

Browser folder sandbox, local storage mount picker, read-only / read-write selector, dan cleanup policy.

Provider BYOK

Form tambah provider, test koneksi, sync model list, tandai model capabilities, dan assign ke pools.

Routing profiles

free, small, balance, frontier, plus user-defined custom route mode bila diperlukan.

Agent swarm

Role editor, fallback role/model, sandbox affinity, tool permission, dan artifact flow antar agent.

Keputusan desain yang disarankan

supaya stabil di Android
1

Jadikan Termux default terminal runtime, bukan sekadar opsi tambahan.

2

Normalisasi semua provider ke External Provider spec tunggal agar router dan swarm tidak vendor-specific.

3

Pisahkan filesystem metadata app dari rootfs agar uninstall tidak merusak data user.

4

Simpan API key melalui secure storage / keystore reference, bukan plain exportable config.

5

Tambahkan healthcheck provider dan dry-run routing sebelum agent swarm dijalankan.

Ringkasnya: app = control plane, Termux = terminal emulator default, sandbox manager = lifecycle Linux, External Provider spec = abstraksi model, dan routing/swarm = execution intelligence.
