Profile Session Spec

Profile bukan cuma konfigurasi, tapi runtime session aktif seperti chat session.

Setiap Project Profile harus menghasilkan active session yang bisa dijalankan, dihentikan sementara, dilanjutkan, dihentikan total, dan diatur waktunya. Session ini menyimpan hubungan hidup antara sandbox, provider, router, workflows, env vars, repos, browser state, dan working agents.

State / aksi
Field minimum
Makna operasional
RUN

Menjalankan session profile.

sessionId, startedAt, activeBindings, timerPolicy
Memasang sandbox, route, agent set, dan screen-aware context untuk profile aktif.
PAUSE

Membekukan aktivitas non-esensial.

pausedAt, suspendedTasks, aiState
Workflow tertentu dan Ai✨ auto-suggest bisa dihentikan tanpa melepas state profile.
RESUME

Melanjutkan session yang dibekukan.

resumedAt, restorePolicy
Mengembalikan agent, router, file mounts, dan panel context ke posisi terakhir.
STOP

Mengakhiri session aktif.

stoppedAt, cleanupPolicy, exportSnapshot
Menutup lifecycle profile, opsional menyimpan snapshot state dan log.
EDIT TIME

Kontrol durasi dan jendela aktivitas.

sessionTTL, aiAutoWindow, workflowWindows
Dipakai untuk batas aktif profile, 5min-Auto Ai✨, atau jadwal kerja terikat profile.

session-rules.txt behavior summary 
- one active profile session at a time by default
- switch profile = prompt to pause or stop current session
- Ai✨ auto mode defaults to 5 minutes then turns off
- explicit user request can execute real actions
- without explicit request, Ai✨ only analyzes and suggests
- proactive notifications allowed but non-destructive
Signals Spec

Sistem pemicu lintas-layer untuk command, workflow, notification, email, git, agent lain, time, task, dan lainnya.

Modul Signals adalah event fabric utama. Semua pemicu masuk ke format sinyal yang seragam, lalu didistribusikan ke profile session, workflow, agents, router, file manager, browser, atau Ai✨Suggest. Dengan ini, sistem tetap modular dan dapat diputus-sambung.

Input sources

Command, workflow.json, notification, email, git hooks, agent outputs, timer, scheduler, task state, browser events.

Normalization

Semua event dinormalisasi ke satu format signal agar mudah diproses oleh router, session runtime, dan Ai✨.

Policies

Signal bisa dibatasi per profile, per layer, per permission, dan per tingkat risiko eksekusi.

Actions

Signal dapat memicu suggest-only, notify-only, queue workflow, run task, atau menunggu approval user.

Flow 01

Receive

Signal diterima dari command, task, email, git, atau notifikasi sistem.

Flow 02

Normalize

Sumber dan payload diterjemahkan ke schema signal tunggal yang bisa dipahami semua modul.

Flow 03

Analyze

Screen Aware atau policy engine menilai konteks, tujuan, risiko, sebab-akibat, dan relevansi terhadap profile aktif.

Flow 04

Act / Suggest

Hasilnya bisa berupa notifikasi proaktif, opsi sugesti, atau eksekusi nyata bila user secara eksplisit meminta.

Ai✨Suggest Agent

Satu model dijadikan agent pembantu lintas-panel, berfungsi menghasilkan bahan input untuk user.

Fungsi utama modul ini adalah Ai Agent generate output dari berbagai sumber untuk jadi bahan input oleh User. Artinya Ai✨Suggest tidak otomatis mengambil alih. Ia menyusun konteks, menyarankan pilihan, menjelaskan sebab-akibat, dan baru mengeksekusi jika user meminta secara eksplisit.

Peran Ai✨Suggest

single-model helper agent
Analyze

Menganalisa screen context, sumber data, struktur, kebutuhan, tujuan, relasi sebab-akibat, dan risiko tindakan.

Suggest

Memberikan pilihan tindakan walau tidak diminta, selama bersifat aman, non-destruktif, dan relevan terhadap panel aktif.

Prepare

Menghasilkan draft command, ringkasan error, perubahan file yang disarankan, prompt lanjutan, atau route recommendation.

Execute

Hanya mengeksekusi nyata bila ada perintah eksplisit user atau workflow policy yang memang mengizinkan tindakan otomatis.

Notify

Mengirim notif proaktif untuk failure, mismatch, peluang optimasi, dependency hilang, kredensial bermasalah, atau task tertunda.

Aturan keamanan

aman kalau user lupa switch off
Default

Toggle Ai✨ default ke mode 5min-Auto / off, bukan always-on permanen.

Expiry

Sesudah 5 menit, mode auto kembali nonaktif kecuali user mengaktifkan ulang.

Non-destructive

Tanpa permintaan eksplisit, Ai✨ terbatas pada analisa, draft, notifikasi, dan saran.

Panel scope

Toggle di setiap header panel berlaku per panel, jadi user bisa aktifkan di Terminal tapi mematikan di Files.

Chat Header

Memberi draft prompt, alternatif tanya, ringkasan konteks percakapan, dan notifikasi proaktif yang aman.

Files Header

Mendeteksi peluang zip/export, rename batch, file orphan, artifact penting, atau script yang layak dipreview.

Browser Header

Menyusun ringkasan halaman, mendeteksi form penting, menandai docs relevan, dan menyiapkan pertanyaan lanjutan.

BYOK — Tab Ai✨

Tambahkan tab khusus “Ai✨” untuk konfigurasi single model agent.

Di modul BYOK, harus ada tab khusus Ai✨ yang lebih ringkas dibanding provider multi-model biasa. Tujuannya adalah mengikat satu model tunggal untuk agent Ai✨Suggest dengan alur: Base URL, API Key, single model, test key, validation, save.

Ai✨ setup flow short UX 
1. user opens BYOK > tab "Ai✨"
2. user enters Base URL
3. user enters API Key
4. user selects single model
5. app runs Test Key
6. validation status shown
7. user clicks Save
8. Ai✨Suggest becomes available in panel toggles

Screen Aware Layer

Ditancapkan ke setiap layer sebagai modul analisa konteks layar.

Layer Screen Aware wajib tertanam ke semua modul utama: Chat, Terminal, Files, Browser, Providers, Agents, Workflow, Project Profiles. Ia membaca konteks visual dan struktural, lalu menghasilkan bahan bantuan untuk user: bukan mengambil alih, melainkan memperkuat pengambilan keputusan.

Kemampuan Screen Aware
Apa yang dianalisa
Output ke user
Context Mapping

Konteks panel aktif.

screen context, sumber, struktur tampilan, panel state
Ringkasan apa yang sedang dilihat user.
Need Detection

Deteksi kebutuhan.

tujuan, hambatan, missing dependency, missing credential
Saran next-step, checklist, atau prompt lanjutan.
Cause–Effect

Hubungan sebab-akibat.

error chain, workflow consequence, file impact, route impact
Penjelasan kenapa sesuatu gagal dan apa efeknya.
Suggestion Engine

Opsional meski tak diminta.

pilihan aman, peluang efisiensi, docs relevan, route hints
Pilihan sugesti proaktif yang aman dan non-destruktif.
Execution Gate

Eksekusi nyata bila diminta.

explicit user intent, policy permission, risk level
Command nyata, file operation, workflow trigger, atau browser action.

proactive-notification.policy safe behavior 
allowed proactive notifications:
- failed workflow
- expired credentials
- missing env vars
- provider validation errors
- route fallback activation
- orphan artifacts
- docs recommendation

not allowed without explicit request:
- destructive delete
- credential overwrite
- repo force push
- arbitrary shell execution

Kesimpulan versi terbaru

Sekarang sistemmu resmi menjadi session-based, signal-driven, screen-aware Android IDE/CLI.

Penambahan profile session, signals, browser internal, Ai✨Suggest, tab BYOK Ai✨, dan toggle Screen Aware per panel membuat arsitektur ini jauh lebih matang. Ia bukan lagi sekadar app builder, tetapi operating surface kerja modular yang digerakkan oleh profile, event, dan konteks layar.

Session Runtime

Profile hidup sebagai session aktif yang bisa run, pause, resume, stop, dan edit time.

Signal Fabric

Semua pemicu dinormalisasi agar bisa diproses oleh workflow, agent, router, file manager, dan browser.

Ai✨ Notif Proaktif

Workflow mendeteksi peluang optimasi route pada profile aktif.

Ringkasnya: Profile = session aktif, Signals = pemicu universal, Ai✨Suggest = agent single-model screen-aware, BYOK Ai✨ = konfigurasi cepat, dan toggle Ai✨ per panel + 5min-Auto/off membuat sistem tetap kuat namun aman.
