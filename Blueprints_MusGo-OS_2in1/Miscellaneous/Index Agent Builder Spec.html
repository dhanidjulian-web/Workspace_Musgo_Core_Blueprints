Provider StatusBYOK

Base URL, API key auto-test, auto-validasi sukses, refresh models, assign route-config per provider.

Project ContextProfile

Sandbox, skill, agent, workflow, schedule, env vars, repos pin, git credentials, dan working agent menempel ke satu profil kerja.

Modul utama

Add External Provider (BYOK) harus jadi citizen utama, bukan pengaturan tersembunyi.

Modul utama provider wajib mendukung penambahan provider eksternal dengan input Provider Base URL, nama provider, API Key, auto-test, auto-validasi jika sukses, dan refresh models. Setelah valid, setiap provider harus punya route-config sendiri.

Provider BYOK Module Spec

mandatory main module
Input

Provider name, base URL, API key, optional headers, compatibility type, timeout policy, dan toggle enable/disable provider.

Auto-test

Begitu user simpan API key, modul otomatis menjalankan healthcheck atau endpoint test. Jika sukses, status provider berubah menjadi validated.

Refresh

Refresh models mengambil model list terbaru dari provider lalu menyimpan metadata model: capability, context, tools, vision, reasoning, pricing tag.

Route Config

Setiap provider punya mapping model untuk provider-auto/free, provider-auto/small, provider-auto/balance, provider-auto/frontier, dan provider-single/model.

Fallback

Jika provider utama gagal, fallback bisa pindah ke provider lain atau ke external router provider, tergantung policy profile/project.

UX alur ideal

tambah provider dalam 4 langkah
01

User isi nama provider dan base URL.

02

User tempel API key lalu klik simpan. App langsung auto-test dan auto-validasi.

03

Jika valid, app refresh models secara otomatis dan tampilkan model picker untuk free/small/balance/frontier/single.

04

Provider siap dipakai oleh chat, agent, workflow, scheduled task, dan project profile tertentu.

provider-validation.flow auto-test + auto-validasi 
1. user submits providerName + baseUrl + apiKey
2. app stores api key into secure storage reference
3. app calls healthcheck endpoint
4. if HTTP success:
   - status = validated
   - refresh models
   - hydrate route-config editor
5. if failed:
   - status = invalid
   - show error details
   - keep draft config for retry
External Routers Provider Spec

Router juga bisa diperlakukan sebagai provider eksternal.

Selain provider model langsung, kamu juga minta External Routers Provider Spec. Ini berarti app harus bisa terhubung ke layanan router eksternal yang memilih model/provider secara remote, tapi tetap tunduk pada Project Profile, policy lokal, dan fallback lokal.

Router sebagai endpoint

Router eksternal punya base URL, auth, route modes, pool policies, dan response schema yang dinormalisasi.

remote route policy sync fallback local

Hybrid routing

Jika external router tersedia, request bisa diarahkan ke sana. Jika mati, local route-config per provider tetap bisa jalan.

redundant resilient offline fallback

Agent-aware routes

Planner, coder, reviewer, runner, atau shell-agent bisa punya route preference berbeda dari external router maupun lokal.

role routing agent affinity cost tiers

router-behavior priority resolution 
priority order:
1. project profile explicit single-model pin
2. project profile explicit route mode
3. external router resolution
4. provider local route-config
5. fallback provider chain
6. emergency offline small/free model

agent override:
- planner -> frontier
- coder -> balance
- runner -> small
- summarizer -> free

Sandbox File Manager Spec

Bukan file picker biasa: ini file workspace engine.

Fitur file manager yang kamu sebutkan sudah cukup untuk disebut workspace-level file system module. Karena ia terhubung ke sandbox, agent, workflow, preview, run, dan GitHub Action, maka posisinya setara dengan panel Files pada IDE modern.

Operasi inti

minimum feature set
CRUD

New file/folder, delete, rename, move, cut, paste, duplicate, dan multi-select operations.

I/O

Import/export file, upload/download antar sandbox dan local storage, serta zip/unzip batch.

Selection

Select one, beberapa, atau semua; lengkap dengan action bar kontekstual.

Bookmarks

Simpan lokasi penting seperti /workspace, /exports, repo root, config root, assets, logs.

Preview/Run

Preview file teks, markdown, json, image, log, lalu run script/command langsung ke sandbox atau Termux session.

GitHub Action

Trigger workflow repository dari file manager context, misalnya untuk deploy, lint, test, atau sync artifacts.
