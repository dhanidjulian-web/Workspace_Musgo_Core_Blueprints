## Quick Start

Given a target enterprise client and product, produce four deliverables:
1. **Enterprise Package** — tiered offering with pricing/SLA logic
2. **Adoption Strategy** — phased rollout plan
3. **Risk Analysis** — compliance, security, operational risks + mitigations
4. **Deployment Model** — technical/organizational deployment approach

Example prompt: "Design an enterprise adoption plan for MusGo targeting a national telco with 5,000 employees, requiring SSO and data residency compliance."

## Workflow

Progress:
- [ ] Step 1: Clarify client profile (industry, size, regulatory environment, existing tech stack)
- [ ] Step 2: Define Enterprise Package (tiers, features, SLA, support model, pricing logic)
- [ ] Step 3: Draft Adoption Strategy (phases: pilot → department rollout → org-wide, with success metrics per phase)
- [ ] Step 4: Conduct Risk Analysis (compliance/legal, security, integration, change management, vendor lock-in)
- [ ] Step 5: Specify Deployment Model (cloud/on-prem/hybrid, integration points, timeline, RACI)
- [ ] Step 6: Synthesize into a single consultative recommendation with next steps

**Step 1 — Clarify client profile:**
Ask/assume: industry vertical, headcount, regulatory framework (GDPR, SOC2, HIPAA, PDP Indonesia, etc.), current IT maturity, decision-maker structure (IT, procurement, legal, business unit).

**Step 2 — Enterprise Package:**
Structure as tiers (e.g., Standard / Premium / Custom). Include: core features, integration support (API/SSO/SCIM), dedicated account management, SLA (uptime, response time), pricing model (per-seat, usage-based, flat enterprise license).

**Step 3 — Adoption Strategy:**
Always phase it:
- Pilot (1 team/department, 4-6 weeks, define success KPIs)
- Controlled rollout (multiple departments, feedback loops)
- Full deployment (org-wide, change management, training)
- Post-adoption (QBRs, expansion opportunities)

**Step 4 — Risk Analysis:**
Cover four categories minimum: Compliance/Legal, Security/Data, Technical/Integration, Organizational/Change. For each risk: likelihood, impact, mitigation.

**Step 5 — Deployment Model:**
Specify: hosting (cloud/on-prem/hybrid), integration architecture (API gateway, SSO/IdP, data sync), migration approach, rollback plan, ownership/RACI matrix.

**Step 6 — Synthesize:**
End with a one-paragraph executive summary and 3 concrete next steps.

## Examples

**Example 1:**
Input: "Enterprise adoption plan for a 5,000-employee national telco, needs SSO and data residency compliance."
Output:
- **Enterprise Package**: Custom tier with dedicated CSM, 99.9% SLA, SCIM/SSO (SAML2), in-country data hosting, annual flat licensing with volume discount.
- **Adoption Strategy**: Phase 1 pilot with IT/network ops team (6 weeks, KPI: 80% daily active use); Phase 2 rollout to customer service + sales (8 weeks); Phase 3 org-wide with mandatory training modules; Phase 4 quarterly business reviews.
- **Risk Analysis**: Compliance — data residency law requires local data center (mitigation: partner with local cloud provider); Security — SSO misconfiguration risk (mitigation: staged IdP testing); Integration — legacy telco billing system incompatibility (mitigation: middleware adapter); Organizational — union/labor resistance to new tooling (mitigation: change champions program).
- **Deployment Model**: Hybrid (in-country cloud region + on-prem gateway for legacy systems), phased migration over 4 months, RACI with client IT owning infra and vendor owning application layer, rollback via feature-flagged release toggles.

**Example 2:**
Input: "Quick enterprise pitch for a 200-person fintech startup wanting fast deployment."
Output:
- **Enterprise Package**: Premium tier, standard SLA (99.5%), self-serve SSO setup, monthly billing.
- **Adoption Strategy**: Single-phase rollout (2 weeks) given small size, with a 1-week pilot in engineering team first.
- **Risk Analysis**: Compliance — fintech regs (PCI-DSS) require audit logging (mitigation: enable built-in audit trail); Security — API key sprawl (mitigation: centralized secrets vault); Organizational — low risk given small size.
- **Deployment Model**: Fully cloud, single-region, direct API integration, no legacy migration needed, deployed in under 3 weeks.

## Best Practices

- Always tie compliance requirements to the client's specific jurisdiction/industry (don't give generic GDPR boilerplate for non-EU clients).
- Size the adoption strategy to the client — a 200-person startup doesn't need a 4-phase, 6-month rollout.
- Quantify risks (likelihood/impact) rather than listing vague concerns.
- Recommend hybrid deployment when legacy systems are mentioned; don't default to pure cloud.
- Include a named owner/RACI for every deployment step — enterprise buyers expect accountability clarity.
- Keep the executive summary short enough for a C-level reader (under 150 words).

## Common Pitfalls

- Don't propose one-size-fits-all packages — always tier and customize.
- Don't skip risk analysis even for "simple" deployments; enterprise buyers expect it as a checkbox.
- Don't recommend on-prem-only or cloud-only without checking for legacy/regulatory constraints first.
- Don't bury the actionable next steps at the end of a long document — always surface them clearly.
- Don't conflate adoption strategy with deployment model — one is organizational/change management, the other is technical/architectural.
